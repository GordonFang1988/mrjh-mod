# 山中石室与山洞素材搜索

玩家导出的 v1.0.10 诊断已足够定位本次问题，无需存档。原始回复没有场景分类，保存的空间为“未知”。旧近似搜索以具体地点文字与素材分类评分，把标为“地下石室”的 `UI451`（西南普通坡城公共汲水井室）排在山洞素材前。图片成功加载，但场景类型不合适。

## 选图变化

仅在模型空间字段缺失、未知或未表达偏好时，使用结构化地点作为素材搜索依据，不解析正文，不改变模型分类、场景 ID 或地点。

- 山洞、岩洞、洞府、洞厅、溶洞等地点可搜索洞内、静修洞穴、石窟与闭关石室。洞口、洞外和洞府前使用洞口素材。
- 没有“闭关”等修饰的石室较模糊，只有上级地点明确含山、崖、岩等地形时，才使用山中石室的素材范围。井室、地窖、墓室和明确的宅院等地点不套用这个规则。
- 地点中的具体房间优先于前缀地点；例如“洞府客房”仍搜索客房。没有同类素材时保留原有近似搜索行为。
- 已给出的模型分类继续通过原有匹配流程。地域、功能和人工选图的语义不变，不依地点推翻模型分类。

## 旧自动误选的修正

读档时，仅检查保存为 `location-fallback` 或继承该结果的 `existing-binding`、原始空间未分类、旧搜索范围为全图库近似匹配的场景。旧图片必须能精确对应当前图包的 ID、版本与地址；已有同类背景、手工背景、手工中性背景、模型已分类的场景和图包中已移除的冻结图片不重新选图。

只有当前地点具有明确的山洞素材范围、旧图位于范围之外、新图在范围内且图包图片可读取时，才更新背景。保留 ref、场景 ID、地点别名、原始分类、正文和命令。新结果冻结到原场景，再次返回或读档不反复更换。

诊断 v2 保持现有格式，增加所选素材和候选素材的 `label`，以及搜索依据中的 `preferredSpaces`、`contextTerm` 和一次修复的 `replacedAssetId`。

## 验证

`node scripts/avgCaveSceneRegression.mjs` 同时支持无图包的机制样本和完整本地图库。可传入诊断 JSON 路径验证当前案例，玩家诊断与图片不会提交。

本次使用 2230 张场景图库复现 `UI451`，修正为 `ST130`（岩壁石室素材）。隔离浏览器使用原诊断的 17 段日志、实际 `AvgStage`、图包读取与 WebP 图片，验证第 13 段、完整播放、重播、诊断字段和读档修复幂等性。没有修改玩家浏览器或存档，没有调用 LLM 或生图接口。
