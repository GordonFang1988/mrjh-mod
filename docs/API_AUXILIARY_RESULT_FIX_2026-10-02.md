## 已确认的程序缺陷

1. v1.1.1 的完整记录预算只支持部分平面标签和数字编号，没有完整支持实际树状快照、章节内嵌区块及普通事实列表。树状资料可能被识别为一整条超大记录，超过4000字符便全部省略，仅留下21字符的提示；冗长章节标题作为重复元数据也会挤掉证据。
2. 实时章节资料还可能有很长的概括/事件说明。直接从已拼好的大字符串选取，不能保证在预算内保留结构化事件的条件和可见性。旧测试只断言输入上限和省略标记，没有断言请求中仍包含有效小说证据。
3. 规划请求末尾复用了主剧情伪历史，要求正文、短期记忆、变量规划和剧情规划，与辅助任务的说明/命令协议冲突。这是可确认的请求设计问题，但现有诊断不能证明它是本次提供方只返回思考的唯一原因。
4. 旧解析器在没有最终回答时尝试从思考文本提取命令；未解析出命令又可静默变成“未产生补丁”。HTTP成功没有记录解析/过滤/应用结果，无法区分不需要更新与没有有效结果。
5. 共用SSE提取器存在另一处兼容缺陷：同一帧出现 reasoning_content（包括空字符串）与 content 时，提前返回思考分支而忽略正式回答。本次诊断的contentChars也为0，故不能把此兼容缺陷认定为该回合的已证实原因；仍需修复并覆盖回归。

提供方返回 stop，输出5319tokens，小于请求上限8192；诊断没有报告长度截断。不能直接归因于输出上限不足，也不能从当前导出判断模型、提供方或代理为什么停止在思考阶段。

## 修复行为

- 大型实时小说滑窗从原始结构选择证据记录，优先当前组硬约束、完整事件时间/前置/触发/阻断条件及可见性，同时为下一组保留空间。仅概括、事件说明等描述性字段可明确节选；超长条件整条省略，不能截成已满足的门槛。
- 元数据按预算限制展示长度，保留分解组与章节身份；500字符预算也优先保留能容纳的一条完整当前组证据。省略仍明确标记，不能凭缺失条件切章。
- 旧快照预算支持树状节点与章节内嵌标签，保留父节点身份和事实归属，不再把整棵树当成一条记录。所有输入总预算及主剧情独立资料策略保留，原始数据集不变。
- 规划请求以任务专用user消息结束，移除主剧情伪历史；明确要求最终说明与命令，内部思考不能替代最终回答。GPT开关和传输协议配置继续保留，不修改用户设置。
- 规划仅解析最终回答。仅思考、空结果、不完整或无效最终回答会明确报错，进入现有阶段重试/跳过流程；不自动为已付费的空最终结果重复发送，也不拿思考中的假设命令写状态。真正的无需更新（无或空命令数组）仍可正常结束。
- SSE同帧保留两个频道，并兼容最后一帧的message.content；不把推理频道伪装成最终回答。
- 诊断新增result：invalid-output / no-update / filtered / ready / applied，以及解析、接受、应用命令数。reason是固定枚举，计数是数字，不保存正文、命令路径、人物姓名或密钥；持久化恢复同样采用白名单。请求status仍独立表示接口状态。
