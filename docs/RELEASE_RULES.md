# 版本与更新日志规则

当前版本基线：1.0.0。此前已完成的内容归入此基线，不补造历史发布版本。

## 版本递增

- 修复、兼容和小幅界面改进：1.0.0 → 1.0.1。
- 向后兼容的新功能或成组功能：1.0.x → 1.1.0。
- 不兼容的协议或存档变更：升级主版本，并说明迁移方式。
- 同一次正式发布只递增一次；开发中的多次修改不单独编号。
- 美术 ZIP 保持独立版本，不因纯资源更新强制升级游戏版本。

## 每次发布

1. 更新 package.json、package-lock.json 与 release/version.ts，三个版本必须一致。
2. 在 release/releaseNotes.ts 顶部添加记录。同一天的更新合并在同一个日期组内，组内按时间从新到旧排列。
3. 每项填写唯一 id、北京时间 HH:mm、版本、标题、简述和玩家能理解的具体变化。只记录已完成内容，不把待开发功能写成已发布。
4. 运行 npm run check:release、TypeScript 与本次变更需要的测试；生产构建自动检查版本和最新日志是否一致。
5. 按明确文件清单提交推送；美术生产文件、个人存档、API 配置和本地测试数据不随游戏发布。

## 展示与提示

参考 COPV2：日期分页，页内显示时间、版本、标题、简述与条目；默认打开最新日期，可浏览历史。
首页每天首次进入提示一次，同一天最新更新 id 变化时再次提示。版权提示关闭后再显示更新日志，避免重叠。
首页版本入口和游戏底部版本入口可随时打开。查看记录仅存本机，不写入游戏存档；本地存储不可用时仍可关闭窗口。
诊断导出包含游戏版本，方便定位线上问题。
