# 红颜卷宗更新修复（2026-10-03）

用户截图显示“同人女主规划”：只有优化输入前的钟灵条目，甘宝宝未加入，互动事件和镜头规划均为零。

## 已复现的代码缺陷

`filterTaskViewCommands` 会把旧数组项内被节选的事实数组，当成拒绝向父数组追加新条目的理由。
模拟钟灵有八条旧事实、输入仅展示其中六条时，新增甘宝宝到女主条目的命令被错误过滤。新增不会覆盖钟灵的旧事实，应独立校验。
`女主姓名` 不在身份字段名单内；直接增加该字段又会把同一人物的不同事件误认成重复，需按人物、事件名和镜头标题分别识别。
统一规划的附加结构参考还使用原创女主根路径作为许可说明及例子，与同人模式激活的根路径冲突。

## 修改

- 追加新数组项时，不因旧项内的节选数组拒绝新增；保留目标数组的重复身份检查和父数组原始索引检查。
- 保留女主姓名等身份字段；女主条目按姓名识别，事件和镜头按各自标题及 ID 识别。
- 结构参考的写入许可和路径例子跟随原创/同人模式，协议标签保持原名。
- 输入筛选的查询加入本次玩家输入；提示词要求核对实际互动对象的事实与关系变化，禁止无依据把所有女性列为女主。
- 诊断新增 `parsedHeroineCommands / acceptedHeroineCommands / appliedHeroineCommands` 三项数值，不记录人物姓名、命令正文或完整提示词。
- 保持规划输入总预算 48000 字符；没有恢复完整历史或整棵规划树输入。
