## 具体修复

- “通用、未知、不适用”和省略的可选字段表示未指定偏好，不作为必须精确相等的体系/功能条件，也不参与加减分。原值仍保存在回合内。
- 空间兼容集中登记，补齐公共堂室、院落、客舍、药房、铸造室、地牢、室内练武等关系。保留体系和用途约束，避免室内/室外、卧室/大厅、佛寺/道观等混用。
- 功能相同的资源优先；相近功能仅在明确的空间组内生效。专用铁匠/铸剑资源优先于普通工坊，避免一个宽泛功能类别遮蔽更近的资源。
- 空间和功能筛选后，先按 LLM 提供的地域、装潢、规模等字段评分。主题和已有画风在最高分中优先，不再直接排除更符合分类的通用图。已绑定图继续冻结。
- 未收录的空间保留为字符串，无候选时显示中性背景；兼容关系使用 Map，不会因 constructor、toString、__proto__ 等合法字符串而访问对象原型并崩溃。
- 场景表支持原有对象结构及数组，取消静默截断。镜头引用统一读取和序列化，支持 s100、自定义引用、安全的属性转义，以及标签和正文不换行的输出。
- JSON 回复先走既有 JSON 规范化路径，再处理标签文本，避免场景分类被修复器变成旁白。严格标签校验的原路径保留。
- ID 和地点不再静默截短；只有建筑/县城而无具体空间的地点不建立房间别名。显式稳定 ID 可以独立绑定并在后续回合引用。
- 润色保留有场景与无场景段落的完整顺序；中性段落使用结构标记清除继承，若润色删除边界则保留原文。
- 手工背景按镜头保留，允许其他镜头修复。已有图片文件缺失时保留选择身份，以便重导图包；精确资源迁移仍检查文件存在。没有实际恢复结果时不计修复、不替换历史对象。
- 诊断识别 JSON/标签文本，提供候选分类、评分和各级筛选计数。JSON 正文中的字面标签不误当成顶层场景块。

## 图库仍缺少的空间

21 个协议空间原本没有精确素材；其中地牢、石窟、思过崖、山中茅屋内、猎户小院已有明确近类可用，本次接通。

剩余 16 个类别没有精确图或已登记的兼容图：

平原、草原、荒原、丘陵、沙漠、戈壁、荒漠、绿洲、瀑布潭边、雪原、冰川、废墟、墓室、门派石阶、塔林、破庙外。

这些属于图包覆盖缺口，需要后续补图和元数据登记。当前保留中性背景，导出会明确提示无对应资源。
